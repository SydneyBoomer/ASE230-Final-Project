<h1>ASE 230 Final Project</h1>

<h2>Objective</h2>

The purpose of the final project is to apply the major server-side programming concepts covered in class by developing a scaled-down version of an established type of web application.

Choose one of the following project categories:

<ul>
<li>E-commerce web application, similar to eBay</li>
<li>Video-sharing web application, similar to YouTube</li>
<li>Social media web application, similar to Facebook</li>
<li>Ticketing web application, similar to Ticketmaster</li>
<li>Job recruitment web application, similar to Indeed</li>
</ul>
You are not expected to recreate the complete commercial website. Instead, you will identify its core server-side functionality, select a realistic subset of those features, and build your own simplified implementation.

The final application must also satisfy the common technical requirements listed below, regardless of which project category you choose.

The purpose of this proposal is to define what you intend to build and demonstrate that your proposed scope is realistic, sufficiently substantial, and aligned with the goals of ASE 230.

<h2>Common Project Requirements</h2>
Every project, regardless of application category, must include the following:

User Interface
<ul>
 <li>Responsive design that works reasonably well on both desktop and mobile devices</li>
 <li>Dynamic content rendering based on server-side data or application state</li>
</ul>
Data and Interaction
<ul>
 <li>Database integration</li>
 <li>Form processing</li>
 <li>User input handling and validation</li>
 <li>Persistent storage and retrieval of application data</li>
</ul>
Security and Access Control
<ul>
 <li>User authentication</li>
 <ul>
  <li>Login</li>
  <li>Logout</li>
 </ul>
 <li>Secure handling of user and application data</li>
 <li>Three levels of access:</li>
 <ul>
  <li>Public access</li>
  <li>Authenticated user access</li>
  <li>Administrator access</li>
 </ul>
</ul>
Your selected application category must be designed around these requirements.

For example, a ticketing application should not simply display events. It should include functionality such as public event browsing, authenticated-user reservations, and administrative event management.

Likewise, an e-commerce application might provide public product browsing, authenticated-user purchasing or listing functionality, and administrative management of products or users.
